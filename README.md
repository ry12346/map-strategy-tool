# 真戦 PK2マップ

「信長の野望 真戦」PK2シーズン向けの非公式マップツールです。

スマホ利用を標準として、地図確認・城関所検索・経路探索・資源州確認に機能を絞っています。

## 主な機能

- PK2マップの閲覧、拡大縮小
- 城・関所検索
- 城名／関所名／資源州の表示切り替え
- 関所レベル表示
- 資源州エリアと境界関所の表示
- 陸路・海上航路を含む経路探索
- 最短移動距離と、足場をつなぐ最小占領マス数の別表示
- 移動ルート／占領ルートの表示切り替え
- 城・関所だけでなく通行可能な任意地点を経路点に指定
- 通行不可関所を指定した迂回探索
- 別ルート候補の表示
- ゲーム座標表示・コピー

## スマホ操作

- 1本指ドラッグ：地図移動
- 2本指：拡大・縮小
- 通行可能地点をタップ：地点メニュー
- 経路点を長押しして上下へ移動：順番変更（変更後に自動再計算）
- 下から開くメニューの上部を下へスワイプ：閉じる
- 上部「城名」「関所名」「資源州」：表示切り替え

海上航路は常に経路探索の対象です。

## 占領マス数の計算

移動できる地形と、通常の隣接占領で足場にできる地形を分けて計算します。ゲームの地形定義にある `can_be_conquered`、`can_be_occupied`、`need_adjacent` が有効で、`is_block`、`on_water` が無効の地形だけを占領経路に使用します。上下左右・斜めの8方向を隣接とします。

- 出発点はすでに確保済みとして、追加で占領するマスだけを数えます。城・本陣・関所などから出発する場合、その施設の全マスを確保済みとします。
- 通常地が到着点の場合は、その到着マスも数えます。施設が到着点の場合は、施設に隣接する足場までを求め、施設攻略は数えません。
- 占領できない葦原や海上航路は、占領の足場に使用しません。葦原内で足場不要の資源地や、遷城専用地も通常の足場には使用しません。
- 通行不可に指定した関所は両方の探索で遮断します。ほかの施設を確保せずに、その施設の内部を占領経路が通り抜けることはありません。
- 途中の施設を経由地に指定した場合は、その施設を確保して次の区間へ進む想定です。施設攻略や遷城の手間は含みません。
- 既存の味方領地、遠隔占領、遷城などによる短縮は反映しません。
- 経由地がある場合は、指定順に各区間の最短経路を求め、重複マスを除いた占領数を表示します。全経由地をまとめた占領数の最適化ではないため、表示名は「占領マス数（経由順）」になります。
- 占領経路がない場合やデータが不足する場合は、その理由を表示します。移動距離を占領数として代用しません。

### 確認例

五老ヶ滝本陣の中心 `1088,1623` から `1087,1636` まで：

| 指標 | マス数 | 条件 |
| --- | ---: | --- |
| 最短移動距離 | 13 | 占領できない葦原も移動可能 |
| 最小占領マス数 | 16 | 本陣の3×3マスは確保済み、到着地を含む |

## 更新方法

公開先の `index.html`、`app.js`、`style.css`、`pk2_embedded_data.js` をこの版のファイルに差し替えてください。画像は前版と同一です。ファイルを一式差し替えても問題ありません。ページ側の読み込みURLは `?v=pk2-v12` に更新しています。

## 開発・データ再生成

通常の利用にはサーバー処理も追加の通信も不要です。占領データは既存の通行可能データとの差分として同梱しており、追加データは約15KBです。

テストは Node.js で実行します。

```sh
node --test tests/route-worker.test.cjs
node --check app.js
```

占領差分の再生成には、同じ版のゲームデータから展開した `res.sbytes` と `land_definitions.json` を使用します。Python 3の標準ライブラリだけで動作します。

```sh
python3 tools/build_occupation_data.py --res /path/to/res.sbytes --definitions /path/to/land_definitions.json --embedded pk2_embedded_data.js --check
```

`--check` を外すと差分データを更新します。異なる版の地形データを使う場合は、移動データとの整合性も確認してください。

## v9

- 「1点戻す」後、2地点以上残っていれば経路を自動で再探索します。
- 「地図から追加」で地点を追加した場合も、2地点以上あれば経路を自動更新します。
- 到着地点が確定済みの状態で「地図から追加」した地点は、到着地点の直前へ経由地として追加します。
- 経路計算中に地点削除・クリアを行っても、古い探索結果が後から復活しないようにしました。
- 地点削除、並べ替え、関所遮断の変更を含め、経路条件を変更した操作では可能な限り自動再探索するよう統一しました。


## v10

- スマホの詳細画面で経路点の長押し並べ替えが動かない問題を修正しました。
